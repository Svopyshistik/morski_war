# Файлова структура проєкту: Лабораторна робота №1 ("Морський бій")

Цей документ описує архітектурну та файлову структуру проєкту для виконання ЛР№1 *"Клас, його будова. Створення та знищення об'єктів"*. Структура розроблена з урахуванням командного розподілу обов'язків, автономності класів, чистоти коду (Clean Architecture) та модульного тестування.

---

## 1. Загальне дерево проекту

```text
morski_war-lab1/

├── src/                        # Файли реалізації (*.cpp)
│   ├── GameManager.cpp         # Реалізація методів та життєвого циклу GameManager
```

## 2. Призначення файлів та модулів за ролями

### 2.1. Модуль «МЕНЕДЖЕР» (Координація та Дії з Use Case)
- **`include/GameManager.h`** та **`src/GameManager.cpp`**:
  - Реалізує патерн *Фасад (Facade)*.
  - Надає інтерфейс для основних прецедентів:
    - `startNewGame(mode)` — старт нової гри (PvP / PvE);
    - `saveGameSession(filename)` / `loadGameSession(filename)` — робота з файлами;
    - `sortShipsByHealth(ascending)` — виконання обов'язкового Use Case "Сортування об'єктів за критеріями";
    - `searchShipById(id)` — виконання обов'язкового Use Case "Пошук об'єктів".
  - Демонструє конструктори (Default, Param) та деструктор.

### 2.2. Модуль «КАРТА» (Генерація поля та валідація)
- **`include/GameBoard.h`** та **`src/GameBoard.cpp`**:
  - Відповідає за 3D-простір поля: рівень $0$ (Повітря / Авіація), $1$ (Вода / Наводні кораблі), $2$ (Під водою / Субмарини).
  - Методи валідації:
    - `validateCoordinates(x, y, z)` — перевірка допустимих діапазонів;
    - `checkShipPlacementRule(x, y, z, size, horizontal)` — перевірка правила класичного морського бою (відступ в 1 клітинку з усіх сторін).
  - Повна автономність: не залежить напряму від інших класів на етапі ЛР№1.

### 2.3. Модуль «БОТИ» (Штучний інтелект та логіка пострілів)
- **`include/AIOpponent.h`** та **`src/AIOpponent.cpp`**:
  - Моделює гравця-комп'ютера з різними рівнями складності.
  - Методи:
    - `generateShotCoordinates(x, y, z)` — обчислення точки удару по відповідному рівню;
    - `analyzeHitResult(x, y, z, hit)` — тактичне навчання бота за результатами влучання;
    - `calculateHitRatio()` — розрахунок відсотка влучності.
  - Демонструє конструктор копіювання (для клонування тактичного стану бота).

### 2.4. Модуль «БІЙ» (Кораблі та спеціальні модифікації)
- **`include/CombatShip.h`** та **`src/CombatShip.cpp`**:
  - Описує корабель з розширеними властивостями:
    - **Танкер з пальним**: метод `triggerDestructionEffect()` викликає вибух навколо себе радіусом 2 клітинки при знищенні;
    - **Міна**: завдає шкоди атакуючому при детонації;
    - **Рухомий човен**: метод `performMove(newX, newY)` змінює координати;
    - **Залповий вогонь у відповідь**: автоматична генерація контрудару при влучанні.
  - Має виразний деструктор `~CombatShip()`, який наочно логує утилізацію об'єкта.

## 3. Файли збірки та конфігурації

### 3.1. `Makefile`
Забезпечує компіляцію однією командою у терміналі під macOS / Linux:
```makefile
CXX = clang++
CXXFLAGS = -std=c++17 -Wall -Wextra -Iinclude
SRC = src/GameManager.cpp src/GameBoard.cpp src/AIOpponent.cpp src/CombatShip.cpp src/main.cpp
TARGET = battleship_app

all: $(TARGET)

$(TARGET): $(SRC)
	$(CXX) $(CXXFLAGS) $(SRC) -o $(TARGET)

run: $(TARGET)
	./$(TARGET)

clean:
	rm -f $(TARGET) *.o
```

### 3.2. `src/main.cpp` (Головний тестовий сценарій)
Демонструє виконання вимог лабораторної роботи:
1. **Створення та знищення об'єктів у стеку** (автоматичний виклик деструктора при закритті блоку `{ ... }`);
2. **Створення та знищення об'єктів у динамічній пам'яті (купі)** за допомогою операторів `new` та `delete`;
3. **Робота конструктора копіювання** (Copy Constructor);
4. **Виклик ключових бізнес-методів** (сортування, пошук, перевірка координат, вибух танкера при знищенні).
